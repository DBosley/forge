## Filter chaining (afternoon)

The first follow-up to #12357 made the planner refuse a payment where one filter pays for another (Plains into Azorius Signet, one of its mana into Dimir Signet), because the payment couldn't do it. That line is legal, so the payment now chains filters instead: when the lands left would come up short, a filter's cost comes from another filter fed the same way first. Planning runs the same code with the sources set aside, so the plan and the payment can't disagree.

A first version that chained only in the payment, with #12357's planner, still failed 16 casts in 1000 games. In those games the planner approved boards where the payment fed a filter from the wrong land. Running the planner through the same code took that to 0.

| Fork state (seeds 1-1000) | Failed casts | Table dead by round 10 | Earliest round win |
|---|---|---|---|
| #12357 alone (`nofix-1000`) | 100 | 77.7% | 7 |
| refusing chains (`nochain-1000`) | 0 | 80.1% | 6 |
| chaining, first version (`chain-v1-1000`) | 0 | 81.0% | 7 |
| chaining with the dead-end check (`final-1000`) | 0 | 80.7% | 6 |

- Chaining against refusing: +0.9 points, McNemar p = 0.049, 211 games changed. Mana spent per round in rounds 1-6 goes up 0.015.
- The one round-6 kill (seed 235) became a round-7 kill. In that game Jace came down a turn earlier: Sol Ring paid for Rakdos Signet and its spare {C} now counts toward the spell. The rest of the kill rounds moved earlier.
- Still left: the shortfall check counts a land as both the mana to start a filter and a color for the spell, so some chains are never tried (Talisman, Caves of Koilos, Azorius Signet, Dimir Signet for Overlord of the Mistmoors now plans as unpayable). Feeding the wrong land to a filter is caught by the planner the same way.

## Chain fix speed and the dead-end check (evening)

Question: does the chain fix cost speed? Compared #12357 alone, refusing chains and chaining: two interleaved 1000-seed runs each (`--threads 12`), a JFR profile, and a stress probe that times one `canPayManaCost` call per spell on boards stacked with filters (a temporary test class, not committed).

- Goldfish games: CPU per game is the same within noise (589, 594 and 591 ms; one build swings 3.5% between runs). The chain code was 0.27% of CPU, all mana payment code 7.6% against 7.2%.
- The slow case was a Plains and six Mystic Gates: 2.1x per call. With Plains spent, the search still tried feeding each Gate from another Gate, though the other Gates' {C} can't pay {W/U}. Every one of those searches was a dead end, 5 levels deep, run 5 times per call.
- Fix (`canStartChain`): the search only runs when something left that costs no mana could pay some filter's cost, or the pool has mana. The last filter of any chain needs one, so nothing that could work is skipped.

| Board (µs per call, 6 spells) | #12357 alone | chaining, first version | with the check |
|---|---|---|---|
| 7 lands, no rocks | 56-80 | 55-80 | 55-80 |
| 3 lands, Sol Ring, Talisman, 3 Signets | 91-113 | 99-131 | 91-132 |
| 2 Plains, 10 Signets | 142-184 | 160-260 | 160-262 |
| Plains, 6 Mystic Gates | 106-136 | 98-280 | 100-186 |

- Same yes/no on all 66 probe checks, same cards tapped in real payments. The Signet boards stay up to 1.4x: their deep chains are real work.
- The check changed 68 of 1000 goldfish games. A detector build that ran the search anyway and reported any chain the check would have skipped fired 0 times in 1000 games. The cause is the chain set: a failed search leaves every filter it tried in it for the rest of that payment, so later picks and the shortfall check saw fewer sources. A replay that skips the dead ends but adds those filters to the set anyway gives back the old games 1000/1000. Metrics EQUIVALENT: table dead by round 10 80.7% against 81.0%, McNemar p = 0.375, 0 failed casts. Against #12357 alone: 77.7% → 80.7%, p = 5.2e-05. Seed 235 is a round-6 kill again.
- Ordinary `sim` games, #12357 alone against the squashed commit: 8 tables of 4 random precons from `res/quest/commanderprecons`, 3 rounds (`simab.py`, output in `prototype/out/sim/chain-vs-12357`). 6 tables played the same game on both builds every round: 40.5 → 40.4 s per game, paired −0.3% (95% −1.1% to +0.5%). Tables 1 and 6 played different games (table 1 took about 135 s on #12357 and 35 s with chaining, the same in all three rounds), so the overall −8.7% the script prints is a different game, not speed.
- The branch is now one commit on #12357 (`95c4bfdf382`, 454/454 tests). `goldfish-v2` carries the same commit as `030e9f7aea4` in place of the two old ones. A last review pass seeded the chain set with the card being paid for (four repeated checks gone, and the shortfall count now skips that card too) and merged the Divination test into the Cancel one; all 1000 goldfish games stayed identical. The old baseline is kept as `out/chain-v1-1000`, the new one is `out/final-1000`.
